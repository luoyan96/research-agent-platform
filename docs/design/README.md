# 界面设计交接 · v1.1

日期：2026-09-21。用户已初步接受这套方向，后续按真实使用调整。下列九张图是同一产品的不同视角，不是必须连续走完的九个步骤。

原图使用 Product Design 工作流和内置 Image Gen 生成。全部内容为示例，尚无对应运行界面；工程入口见 [开发交接](../development-handoff.md)。

| 页面 | 何时使用 |
| --- | --- |
| [01 需求入口](v1.1/01-entry.png) | 自然语言提出需求；增加一个轻量的“实验室任务”入口 |
| [02 协作方案](v1.1/02-plan.png) | 查看本人、智能体、同伴分工及缺口；修改并确认 |
| [03 聚焦待办](v1.1/03-progress.png) | 处理当前需要自己的判断，不替代完整任务详情 |
| [04 成员认领](v1.1/04-claim.png) | 理解交付、验收和投入后选择承接 |
| [05 能力选用](v1.1/05-capabilities.png) | 个人按需要查看或调整执行方式 |
| [06 补充能力](v1.1/06-create-capability.png) | 从缺口形成能力草案并试跑；默认私有 |
| [07 交付验收](v1.1/07-review.png) | 查看成果、要求修改或接受；共享反馈另行选择 |
| [08 实验室总览](v1.1/08-lab-overview.png) | 当前可见任务全貌、人员承诺与可用时间 |
| [09 任务详情](v1.1/09-task-detail.png) | 一个任务的交付物、执行者、节点、状态和依赖 |

导航：对话首页 ↔ 实验室总览 → 任务详情 → 按需进入判断、认领、能力或验收。看板和对话更新同一数据，不重复录入。

布局：暖白背景、深灰文字、克制的绿色强调；无固定侧栏。入口聚焦对话，总览允许更高信息密度，任务详情按表格呈现。公共能力和私有能力在各自可见范围展示，不把个人能力页直接嵌入他人可见任务。

示例中页 03 与页 09 表示不同时间点的状态；正式实现不复制这些静态状态。界面没有画到的加载、失败、空数据、不可访问、邀请拒绝、取消与重试，需要依据业务规则补齐。
