# 第一阶段：在科研小组验证任务与能力匹配

日期：2026-09-30。当前决定：先完成组内可用与真实试用，长期保留跨领域的任务与能力匹配方向。本文是当前范围和下一批工作入口；工程状态见 [G5a 共同复核](development/reports/G5a-overall-2026-09-30.md)。

## 目标、用户与阶段名称

长期产品让任务找到合适的人与 AI 能力，经过确认、执行、交付和反馈，改善后续协作。科研是首个落地场景；是否能扩展到其他知识工作团队，需要以后验证。

第一阶段先服务一个真实小组：任务发起与协调者、愿意承接的成员、验收人，以及少量公共能力维护者。博后、青年教师等同时亲自工作并协调他人的成员是首批核心用户假设；5—20 人团队是招募参考，不是容量上限或已验证市场。成员也要获得清晰要求、方便交付和可用能力，不能只增加填表与汇报负担。

**产品第一阶段 P1 不等于前端 F1 或集成关口 G1。** P1 包含原路线图 M0—M2 的最小范围；F/B 是开发批次，G 是工程验收。G1 只证明真实人类协作，不能据此宣称 AI 匹配、持续执行、知识复用或试点成功。

## 首批工作与交付

选择正在发生、材料允许使用的一项任务启动，例如项目指标与证据核对、申请材料协作、学生任务安排。具体课题、姓名、资料、期限和实际状态留在受控运行空间，不写进公开 Git。过往提出的截止日期不自动沿用；已过去的任务可以作为回顾案例，但不能伪装成仍在进行的试点。

一个完整过程是：描述目标 → 得到并修改协作单 → 确认本人/成员/公共能力的分工 → 接受或认领 → 执行与处理卡点 → 按版本交付、修改、验收 → 下次复用获准的结论。

## 暂不纳入 P1

公开能力市场、跨学校自主派发、支付分成、自动发布能力、完整科研行政/经费/人事系统、每校独立代码分支、一次上线全部十项 Skills。论文、项目、知识产权等是任务语境，不是必须同时建成的独立产品线。

可以以后探索付费试点、标准产品加实施或有限定制；收入、支付渠道和采购意愿另行验证。共性需求优先进入同一产品，可配置差异通过模板与规则承接。组内成功不证明全国市场规模、付费需求或跨组织网络效应。

## P1 通过条件

建议用至少两项有真实交付的任务观察完整过程，其中至少一名非开发成员独立承接并交付；至少一次真实公共 AI 产物经人检查；一次后续任务正确复用获准结论。记录协作方案修改原因、成果采用情况、协调与检查返工投入、开发者介入和运行维护成本。数量是小组试点的工作标准，不是市场统计样本。

发生越权、强制共享私人方法、虚构执行或丢失已确认承诺时不能通过。未发生自然重复需求时明确“留存/复用待观察”，不靠让用户重复演示补齐。若需要工程人员不断代操作，或新增维护与返工抵消收益，收窄或修正后继续验证。

正式账号与备份恢复工具已通过；多人真实试用前仍需在选定主机上配置实际账号、证书/访问边界和维护支持。开发 A/B/C 账号和 localhost 演示不作为正式部署。具体主机与部署动作单独执行，不由本次文档更新自动触发。
