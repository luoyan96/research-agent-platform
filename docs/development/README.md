## 阶段对应

| 阶段关口 | 后端交付 | 前端交付 | 用户能核对什么 | 对应总交接 |
| --- | --- | --- | --- | --- |
| G0：统一基础 | B0 契约、架构决定、Harness 核查 | F0 入口 / 总览 / 详情的演示预览 | 两边采用相同字段和状态；能看到简洁界面；明确哪些只是演示 | D0 |
| G1：人的协作 | B1 身份、持久化任务、承接与验收 | F1 接真实服务完成协作主线 | A 安排、B 接下并交付、A 验收；刷新和重启不丢失 | D1 + D2 的主线 |
| G2：协调与异常 | B2 依赖、变更、取消、聚合与附件 | F2 总览、人员、完整详情与异常处理 | 进度一致、卡点真实、承诺不被静默覆盖、越权访问被拒绝 | D1 + D2 的完整规则 |
| G3：AI 真执行 | B3 真实规划、Harness、后台运行 | F3 异步规划与受控回复、真实运行与待处理事项 | 真实生成建议和交付，关闭浏览器仍运行；失败与中断可辨认 | D3 |
| G4a：最小授权复用 | 结论/来源/权限、公共能力版本与人工维护 | 在任务上下文查看和复用获准结论 | A14 最小真实范围；个人方法可留在平台外 | D4 必要部分 |
| G4b：完整能力管理 | 私人能力托管、试跑、发布与停用 | 创建/选用/发布 UI | A13 与完整 A14；G4a 不等于完整 G4 | D4 后续 |
| G5a：试用准备（已通过） | 正式账号、运行和备份恢复 | 首次使用/故障指引与联调 | 合成环境 R1—R5；准备完成不等于真实试用通过 | D5 准备 |
| G5b：组内试用（待执行） | 修复真实服务阻碍 | 修复真实使用阻碍 | 非开发成员独立完成真实任务，记录协调成本和限制 | D5 |

G5 可在 P1 必要的 G0—G3 和 G4a 通过后开展；完整能力托管 G4b 不作为默认前置。若开放私人能力托管，则先完成 A13，不以缩小范围跳过权限验证。

G1 可以通过手工录入或编辑方案验证真实多人协作，模型规划留在 G3。该阶段不宣称自然语言匹配已经实现。G0 的演示预览也不等于 G1。

G1 的底层权限、版本、去重和任务 / 运行分离不能延后；G2 扩展它们的场景覆盖。未交付的命令应明确不可用，不开放没有保护的快捷操作。

## 分工与集成

- **后端 AI**：服务、数据库迁移、共享契约、Harness 适配、服务测试。负责接口与状态的唯一权威定义。
- **前端 AI**：浏览器界面、客户端状态和契约客户端、界面测试与截图。不私自定义另一份后端状态机。
- **集成人**：由负责验收的主任务承担，维护阶段报告、协调接口变化并集成两个分支。无需为此另建一个完整应用。
- 各用独立工作目录或 worktree、独立任务分支。初始基于 `docs/product-requirements-review` 的最新共享文档；后续以前一关集成通过的提交为共同基线。不要切换或重置另一个 AI 正在工作的目录。
- B0 登记真实目录、命令、共享契约位置和版本。前端取得该契约提交后再做真实服务联调；不能只说“字段应该差不多”。
- 根级 workspace、锁文件和 CI 变更在各自 PR 说明，集成人处理合并并重新验证；不要让双方覆盖彼此未提交的更改。
- 不要求人为批准每个技术实现细节；每个 prompt 明确本批次范围，完成后提交阶段报告，等待下一批次指令。部署另行决定。

## 每次提交统一报告

阶段与分支、基线和契约版本；已完成与未完成；启动命令与必要配置名（不含值）；测试命令 / 结果；对应案例证据；阻塞及影响；下阶段依赖。前端附主要页面截图和操作路径，后端附 API / 持久化 / 权限证据。

开发阶段记录放在 `docs/development/reports/`（实施时创建），只提交合成、脱敏证据；真实研究材料、令牌和内部日志留在运行环境。检查通过不自动等于产品验收通过。
