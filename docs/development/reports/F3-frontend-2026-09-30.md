## 实现与操作路径

1. 密码登录后，在唯一需求入口填写目标，点“发送”。客户端调用 auto 意图，由服务 / 模型判断草案、进度、可承接查询；六个主题按钮只预填输入，不进行关键词分类。手工创建方案继续可用。
2. `#/planning/<id>` 如实显示排队 / 生成 / 失败 / 中断 / 取消 / 完整回复。后台轮询不伪造 token 流、进度百分比或成功动画。完整共享 Schema 校验后才显示草案入口；所有模型文字转义，不执行 HTML、脚本或任意组件。
3. 打开已保存草案重新读取最新版本，在原有协作单编辑、保存、确认。“让 AI 修改这份已保存草案”传同一 planId / version；冲突保留原内容与修改输入，刷新比较新旧版本，由用户明确采用。已确认承诺仍走 G2 协商。
4. “现在进行到哪里”“我能接什么”返回受控任务摘要、服务读取时刻、授权任务与缺口。历史回复的操作进入最新对象，重新校验版本 / 权限；不从任务数量推断人员负荷。
5. 任务详情内“公共能力运行”显示真实运行、来源附件版本 / 哈希、能力版本、模型 / Harness、累计预算和实际用量。展开“能力、材料与新运行授权”，上传本任务 text/plain 后明确选择材料，再启动。available 仅表示已配置，不保证运行成功。
6. 运行状态与任务状态独立。候选含引文、缺口和限制；“确认提交此候选为交付”之后仍需按交付版本验收。失败 / 等待输入进入本人待处理。只有服务 allowedActions 开放取消、重试、候选提交；未知用量的中断不开放盲目重试。
7. 输入 / 不确定请求在同账号失效后保留；重试复用原 key / body。显式退出或换账号清除。回复持续重验授权，断线立即清除受限内容；任务沿用 G2 快照和撤权语义。

## 启动与重跑

在本独立 worktree 执行 `pnpm install --frozen-lockfile`、`pnpm build`。按 [B3 交接](../b3-handoff.md) 准备被 Git 忽略的私有环境文件；DEEPSEEK_API_KEY 只加载到服务 / worker，不送入 Vite、浏览器或报告。配置独立 DATABASE_PATH、BLOB_ROOT、TEST_CREDENTIALS_FILE、B3_AI_ENABLED=1、DEEPSEEK_MODEL=deepseek-v4-flash、HOST=127.0.0.1、PORT=3100、APP_ORIGIN=http://127.0.0.1:4185。

```powershell
node --env-file=.env apps/api/dist/manage.js migrate
node --env-file=.env apps/api/dist/manage.js seed
node --env-file=.env apps/api/dist/credentials.js
node --env-file=.env apps/api/dist/capability-config.js enable lab_synthetic member_A
node --env-file=.env apps/api/dist/main.js
# 另一终端，同一服务配置与数据库
node --env-file=.env apps/api/dist/worker.js
# 前端终端只运行 Vite，不加载私有 .env
pnpm --filter @research-agent/web dev --port 4185
```

浏览器打开 `http://127.0.0.1:4185`，用本地随机 credentials 文件的 A/B/C 登录。以上 seed / credentials 仅本地合成验证，不用于生产身份配置。

脚本通用环境：PLAYWRIGHT_MODULE 指向本机 Playwright ESM，F1_BROWSER_CHANNEL=msedge，F1_BASE_URL=http://127.0.0.1:4185，F1_CREDENTIALS_FILE 指向当前测试库随机账号文件；F3_EVIDENCE_DIR 选择独立证据目录。不同套件使用独立合成数据库，避免账号登录限流累计。

- `node apps/web/scripts/check-f3-browser.mjs`：需要已启动真实 API + worker；会产生真实模型用量，主线 7 组。
- `node --env-file=.env apps/web/scripts/check-f3-resilience-browser.mjs`：8 组，管理自己的 3100 API 与 worker；先停止该测试库其他 API / worker，使用新合成库；故意产生真实失败 / 取消 / 中断。
- `node --env-file=.env apps/web/scripts/check-f3-ui-browser.mjs`：3 组，管理自己的 3100 API，不启动 worker；能力须已配置。用于确定性 UI，不作为模型成功证据。
- 原 check-f1-browser（--manage-api）、check-f1-session-browser、check-f2a-browser、check-f2b-browser 保留。各自使用新库；历史回归 B3_AI_ENABLED=0。
- 根 `pnpm run ci` 不调用真实模型。生产浏览器检查用 `pnpm --filter @research-agent/web preview --port 4186`，停止 API 再访问带 scenario 参数的页面。

## 剩余边界

共同 G3 尚待独立复核。首个能力只支持同任务 UTF-8 text/plain（最多 10 文件 / 合计 20000 字节）；不含 OCR、联网搜索或私人方法。规划页面本批为文字需求 / 同草案修改，不增加跨任务私有材料选择器。服务没有规划请求历史列表端点；运行可经任务 / 待处理找回，已生成草案经草案列表找回，尚在生成的规划请求需保留当前链接。模型可能输出非法结构或超过输出限制，页面保留真实失败及手工路径。引文匹配不等于科学真实性核验，费用未知不估算。预算未知或 worker 租约中断不能承诺外部调用恰好一次；只能依服务允许动作重新授权。

上述是已声明的 B3 范围与运行限制，没有凭据阻塞。私有配置、随机密码、数据库、模型内部日志均未提交。本轮停止在 F3，等待共同 G3 发布同一集成基线。
