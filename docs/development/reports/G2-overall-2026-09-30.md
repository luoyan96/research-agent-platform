## 验收判断与边界

- **A6**：未验收的前置交付阻止下游开始；自依赖/间接环被拒绝。前置变化记录影响并阻塞相关任务，重新绑定、复核影响和恢复分别执行；已有成果及验收历史保留。目前仅开放 `accepted_deliverable` 依赖，`confirmed_decision` 仍明确不可用，不把它计为已交付。
- **A7**：待接受变更与原有效承诺同时显示；拒绝不修改原安排，必要成员全部接受才更新。旧版本冲突保留输入并提供比较，不能静默覆盖承诺。
- **A8**：退出后旧访问失效，转交候选人只先获安全摘要、另行接受才承担。取消停止待派发意图；下载、提交及幂等缓存重放重新鉴权。附件引用绑定交付版本，撤回保留历史而拒绝内容读取。这里验证的是派发意图与访问控制，尚无真实 worker 或通知执行。
- **A9**：详情、授权总览、待回应事项及成员承诺来自同一服务。人员承诺/可用时间不等于实际负荷；当前使用快照检查与手动刷新，没有实时推送。可见页面通常 15—30 秒发现快照失效；后台页不保证即时发现，已下载副本也不能远程追回。

附件当前支持 1 byte—10 MiB 的 UTF-8 文本、PDF、PNG，类型/签名检查不等于病毒扫描。私有文件目录、逐次鉴权和哈希校验已验证；备份恢复、容量运维、崩溃遗留文件清理等正式运行事项未验收。依赖编辑使用授权任务 ID，尚无可视化选择器。这些边界保留，不扩大为部署或全部目标功能通过。

Harness 最新既有核查仍是 2026-09-21 的固定依赖安装阻塞；本次没有重新核查上游或调用模型，不能推断所有现行版本都不可用，也不能称真实 AI 已接通。

## 远端 CI 测试修复

第一次推送至 `9a9364f5cb8d3c01549e8d007846116bb7ff47a6` 后，[远端运行](https://github.com/luoyan96/research-agent-platform/actions/runs/36656439400)的 Linux / Node 24 通过，Node 22 与 Windows 失败。保留失败记录，未通过反复重跑掩盖问题。

1. **权限测试串扰**：先前并发认领若由 C 获胜，C 有权读取该任务正文。但后续分页测试使用所有任务共用的 `RESTRICTED_INPUT_SENTINEL` 判断泄露，误把 C 已授权的正文也判为越权。先补 C 确定认领的合成任务，复现原断言失败；再用不同标记分别核对私密正文、未认领摘要与 C 本人正文。保留原有禁止泄露任务 ID、人员承诺和跨身份游标的检查，并增加未授权详情 404、摘要投影和合法正文可见的断言。未修改服务鉴权逻辑。
2. **Windows 旧库准备超时**：B1→当前、B2a→当前两项测试在 5 秒上限失败。此前数据复制已批量提交，但构造旧表结构仍逐条自动提交，触发大量 FULL 同步。现在把旧 schema 的构造也放入准备事务，在真正调用迁移前提交。真实迁移仍独立执行两次，完整保留旧数据/校验和/会话/交付断言；未调整超时、降低同步级别、裁剪资料或改动迁移实现。

修复后服务专项 **32 项通过**，完整根 CI 仍为 **175 项通过**。业务代码和前端未改，因此 17/15/11/7 组浏览器证据仍对应最终业务实现，无需为测试准备改动重复运行。最终远端检查必须采用包含修复的最新 PR 提交，不能以第一次失败的提交作为下一批共同基线。
