## 环境、启动与前端交接

实际环境 Windows、Node 24.19.0、SQLite 3.53.3、pnpm 11.21.0、TypeScript 6.0.3、Zod 4.1.12。Fastify 5.12.5 固定在锁文件；原 Skills YAML 从 2.8.1 更新 2.8.3，原因是审计所见已知问题已获修复，不改动 Skills 正文。现有 Node 22.19/Linux 和 Node 24/Windows/Linux CI 矩阵保留；本地仅验证上述 Windows 环境，远端结果以 PR checks 为准。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm db:migrate
pnpm db:seed
pnpm api:start
```

从仓库根运行。配置名：NODE_ENV、HOST、PORT、DATABASE_PATH、BLOB_ROOT（无凭据值）。默认地址 127.0.0.1:3100；数据写入 Git 忽略的 .runtime。生产要求显式绝对数据路径；实际产品登录在 B1 前不可用。

前端依赖 `@research-agent-platform/contracts: workspace:*`，根导出 routes / RequestFor / ResponseFor / taskColumns / contractVersion；演示单独导入 `@research-agent-platform/contracts/fixtures`。静态 [examples.json](../../../packages/contracts/examples.json) 包含版本标记和 synthetic=true；[openapi.json](../../../packages/contracts/openapi.json) 是完整 HTTP 形状；[protocol.md](../../../packages/contracts/protocol.md) 固定认证、CSRF、错误、分页、重试与私有边界。

```sh
curl -i http://127.0.0.1:3100/api/v1/health/ready
```

迁移和存储就绪后的实际响应形状（由进程检查确认）：

```json
{"data":{"status":"ok","contractVersion":"0.1.0","checks":{"database":"ok","storage":"ok","authentication":"not_implemented","harness":"not_verified"}}}
```

未迁移时 HTTP 503，status=unavailable、database/storage=unavailable；不能用 live 的 200 代替 ready。

以下是 **B1 合成请求示例，B0 实际返回 501**：

```http
POST /api/v1/tasks/task_claim/claim
Content-Type: application/json
Idempotency-Key: synthetic_command_0001
Cookie: rap_session=<future-session>
X-CSRF-Token: <future-csrf-token>

{"expectedVersion":1}
```

版本冲突样例（并非已执行 B1）：

```json
{"error":{"code":"VERSION_CONFLICT","message":"合成错误，未执行真实业务","requestId":"request_synthetic"}}
```
