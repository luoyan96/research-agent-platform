# 后端开发指南

日期：2026-09-21。状态：待实施。先读 [AGENTS.md](../../AGENTS.md)、[总交接](../development-handoff.md)、[共同契约](contracts.md)、[任务分配规则](../task-allocation.md)。启动用 [B0 prompt](prompts.md#后端第一步-b0)。

## 责任范围

负责真实身份、权限、事务数据库、文件存储、任务状态、分配、派发、Harness 适配、资料隔离和服务验证。共享契约由后端维护，前端从同源取得。科学领域逻辑仍放 research-core，Skill 正文仍在 agents/skills，Harness 适配仍在其集成目录。

服务应用、worker 和契约包目录在 B0 决定并写入架构记录。不要把现有本地 ArtifactStore 扩成多进程修改同一索引的权威数据库，不复制上游 Harness 源码，不用类型占位绕开接入失败。

## B0 · 接口、存储和运行基础

**输入**：现有基础包、总交接、接口语义草案、九张设计图。

**要做**：

- 检查现有代码和检查命令。记录服务器框架、事务数据库、文件存储、认证方式、开发启动与迁移方式；核实并固定依赖版本。
- 将 contracts.md 落成共享的可执行 Schema / 类型、精确接口定义及合成样例，说明认证、版本、幂等、错误、事件与分页。
- 提供可以启动的最小服务骨架和健康检查，响应反映真实依赖状态；如果数据库尚未连通，不把 readiness 报为成功。
- 准备后续成员权限和任务表的迁移计划、事务边界和可靠派发策略；实现必要的基础迁移及开发种子机制，开发身份绕过不能进入生产配置。
- 核实固定 Harness 版本的安装、适配边界及最小真实调用。若依赖、环境或凭据不足，记录准确证据和对 B3 的影响，不阻塞独立的人类协作服务工作。

**交付**：架构与启动说明、契约版本 / commit、Schema 与样例校验、最小服务、接入核查报告、前端需要的配置名与调用示例。不提交密钥值。

**验收**：G0-B；前端可以按精确契约使用样例，健康状态真实；现有检查仍通过。只做计划文字、没有可验证契约，不算本阶段完成。真实 Harness 未接通时明确列为 B3 未通过，不能标作已完成执行。

## B1 · 人的任务协作闭环

**前置**：B0 契约已集成，前端可以引用同一版本。

**要做**：

- 成员身份与会话；任务可见范围；服务端鉴权；方案版本、任务、邀请、认领、承诺、纯文本交付与验收持久化。
- 支持结构化草案编辑和确认。模型尚未配置时明确不可用；允许先手工编辑，不假装是模型生成。
- 确认事务、稳定任务身份、并发认领、命令去重、拒绝和退回修改；隔离 task、assignment、execution 状态。
- 确认前不产生有效分配；接受前不登记已承诺；提交后仅待验收，验收通过才完成。数据库保存版本与事件。
- 提供前端联调的合成 A/B/C 成员和任务，C 用于无权访问测试；种子可重复执行且仅限测试环境。

**交付**：可运行服务、迁移、真实 API、接口测试、重启读取证据；为前端提供基线提交与必要请求示例。

**验收**：G1-B 的 A1–A5；真实事务数据库上完成并发 / 重试验证；直接请求不能越权。用内存仓库、mock 服务或客户端状态代替持久化不得过关。

## B2 · 实验室协调与异常

**前置**：B1 服务可与 F1 联调。

**要做**：

- 依赖图校验、前置交付检查、阻塞与恢复、变更提议和重新接受、退出 / 转交、取消及权限撤回。
- 任务详情、实验室 / 我的范围、四列聚合、父子任务摘要、事件与更新时间；聚合前先做权限裁剪。
- 人员公开承诺和本人填写的可用时间，标记适用区间与更新时间；不按任务数量推断负荷。
- 真实附件上传与下载、版本和来源；撤权影响后续下载，不向无权用户返回存储位置。
- 将任务更新与派发事件放在可靠事务边界中，为后续 worker 准备；不启动未经确认的真实执行。

**交付**：聚合 / 附件接口、状态迁移测试、两会话一致性和异常处理证据。

**验收**：G2-B 的 A6–A9；依赖不能成环；旧版本不能覆盖新承诺；取消与撤权生效；列表、计数、搜索和错误均不泄露不可见资料。

## B3 · 真实 AI 与持久执行

**前置**：B2 的授权、依赖、版本和派发规则有效；固定 Harness 版本已验证。

**要做**：

- 使用授权背景、公共能力及公开成员信息生成结构化草案，校验模型输出；无依据的日期和承诺保持待确认。
- 模型和服务凭据仅在服务端，提供必要配置说明；真实访问不足时保留失败，不改用假结果。
- 接通至少一个可核对的公共能力，从实际运行得到交付候选；标记能力版本、输入范围、用量和来源。
- worker 处理队列、依赖检查、预算、等待输入、有限重试、取消、超时、重启恢复与中断；晚到事件不能覆盖取消或撤权。
- 对外部操作采用幂等或显式不确定结果处理，不能承诺任意外部动作“恰好一次”。效果不明时交人处理。

**交付**：真实运行记录及产物、关闭浏览器和服务重启案例、失败 / 取消 / 用量证据、兼容版本记录。

**验收**：G3-B 的 A10–A12；根 CI 通过不能替代真实 Harness 通路验证。测试双可以用于单元测试，不能替代本阶段成功证据。

## B4 · 能力与知识的权限内复用

**前置**：B3 执行真实可用。

**要做**：

- 公共与本人私有能力分别查询 / 执行，个人运行记录不进入共同上下文、错误或导出。
- 能力草案默认私有；记录样例、真实试跑结果、版本与明确发布授权；停用阻止新调用。
- 按任务权限保存已确认结论和必要来源；反馈共享独立于验收，拒绝共享不影响交付通过。
- 公共能力用明确获准的样例改进、验证后发布；个人改进留在私有范围，版本可追溯与停用。

**交付**：能力和知识接口、权限矩阵测试、真实试跑与新任务复用证据。

**验收**：G4-B 的 A13–A14；对其他成员和任务发起人验证不泄露私有方法。应用权限与服务器管理员的可读范围分别说明，不虚称加密隔离。

## 每阶段结束

执行 AGENTS.md 要求的 `pnpm run ci` 和该阶段新增服务 / 集成验证，报告实际结果与失败。检查脚本必须覆盖新增服务包，不能只跑原有两个基础包便声称新服务测试通过。按[阶段报告模板](acceptance.md#阶段报告模板)交付一个可审查 PR；不自行部署、合并或跨入下一批次。
