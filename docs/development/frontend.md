# 前端开发指南

日期：2026-09-21。状态：待实施。先读 [AGENTS.md](../../AGENTS.md)、[设计索引与 PNG](../design/README.md)、[共同契约](contracts.md)、[总交接](../development-handoff.md)。启动用 [F0 prompt](prompts.md#前端第一步-f0)。

## 责任范围与界面原则

前端负责可理解、可操作的浏览器界面，使用共享契约和真实服务；状态、权限、承诺与验收由服务端决定。复用暖白背景、深灰文字和绿色强调，不加固定侧栏或将六类任务做成六套应用。

保持“对话入口 ↔ 实验室总览 → 任务详情”的轻量导航。本人需要决定、成员认领、能力选择和验收按需进入。任务页不泄露参与者的私有能力，能接任务不要求先建立个人智能体。

## F0 · 设计还原与前端基础

**输入**：九张图片；B0 的共享契约，或其尚未完成时的明确草案版本。

**要做**：

- 逐张查看相关 PNG，记录导航、基础组件与数据需要；选择并核实前端栈，记录版本，与 B0 协调 workspace / 类型共享方式。
- 建立前端应用骨架。先还原 01 入口、08 实验室总览、09 任务详情的桌面布局与导航，其他页先保留明确阶段清单。
- 用隔离的 fixture adapter 预览合成数据，标注“演示数据 · 尚未连接服务”；有共享 Schema 后用它校验样例，不能把重复私有 DTO 当作最终契约。
- 展示空列表、加载、错误、较长标题和窄屏情况；桌面信息可读，窄屏不裁掉关键操作。基本键盘导航与状态不只依赖颜色。
- 演示模式必须显式启动；真实模式、生产构建和发布配置不得静默回退 fixtures。服务端机密不得进入前端配置。

**交付**：能启动的预览、三页截图、组件与页面清单、演示 / 真实适配边界、所依据契约版本、前端依赖和启动说明。

**验收**：G0-F；图与实际页面对照，主导航可用。F0 可以在 B0 未完成时做视觉准备，但 G0 通过前双方必须采用同一冻结契约，F1 才能开始真实联调。

## F1 · 双账号的人类协作主线

**前置**：B0 契约集成通过；B1 对应接口已交付，或前端只在显式演示环境提前开发同契约组件。

**要做**：

- 接真实身份和会话；同一界面支持 A 发起人、B 承接人，真实模式不能通过本地切换名字冒充认证。
- 从入口创建 / 继续真实草案，修改结构化方案并确认；后端未接模型时明确说明 AI 建议暂不可用，提供手工编辑入口。
- 邀请接受 / 拒绝、开放认领、实际开始、文本成果提交、退回修改与验收。默认无需提交个人工具名称或过程日志。
- 展示当前版本、提交状态、冲突 / 认领失败。确认和提交的相同逻辑请求重试复用稳定幂等键；新意图使用新键。
- 请求失败保留用户未提交内容；等待响应不提前显示已完成。刷新从服务取权威数据，不只靠 localStorage。
- 任务详情能展示本阶段的真实承诺与交付；总览未接完整接口时保持明确未完成状态，不能混入演示数据。

**交付**：七个主线相关页面 / 状态的可用部分、两独立登录会话的完整操作记录、接口错误与恢复证据。

**验收**：G1-F；与后端共享 A1–A5 案例，浏览器页面和后端记录一致。仅 fixture 演示不算通过。

## F2 · 实验室全貌与复杂协调

**前置**：B2 对应服务已交付，G1 通过。

**要做**：

- 总览接真实聚合、分页和实验室 / 我参与的筛选；任务状态来自共享映射。已取消保留单独入口，不混作完成。
- 详情呈现子任务、执行者、时间来源、依赖、已有交付与最近更新；“已验收项数”不得标作实际工时完成比例。
- 人员可用情况显示本人填写的周期与更新时间；没有数据时为未知。不能把成员当前任务数量当忙闲或绩效分数。
- 变更展示差异与影响，明确待对方接受；实现受阻、退出 / 转交、取消、撤权、文件上传 / 下载与验收版本。
- 更新订阅或轮询包含断线 / 过期提示和重新同步；前端撤权后清理缓存、关闭仍暴露旧数据的视图。
- 所有提醒、搜索、导出与人员聚合只消费授权数据；接到 403 / 404 不继续展示旧缓存中的受限内容。

**交付**：两会话同步演示；断线、冲突、取消、权限变化和空数据截图 / 记录。

**验收**：G2-F，A6–A9；可在无需不断切换页面的情况下知道谁做什么、何时交付、哪里卡住。

## F3 · 真实 AI 建议与后台执行

**前置**：B3 提供真实规划与运行接口，G2 通过。

**要做**：

- 一句话到真实草案，生成 / 修改 / 失败状态清楚；生成过程中的片段不能提前当成已确认安排。
- 显示排队、运行、等待输入、失败、中断、取消、成功产物及用量限制；运行结束与任务验收分别呈现。
- 需要人的事项进入聚焦待办。用户关闭页面后再回来，从服务恢复状态；取消、重试遵守服务端命令规则。
- 模型未配置、额度不足、执行失败有具体可采取的动作，不显示“正在替你做”但实际没有运行。

**交付**：真实模型建议、真实公共能力交付、离开页面后回看、失败恢复的操作证据。

**验收**：G3-F，A10–A12；至少一个案例经真实 Harness 产生交付。页面流畅不替代实际执行。

## F4 · 私有能力与知识复用

**前置**：B4 对应服务有效，G3 通过。

**要做**：

- 本人才能看到自己的私有能力，选用是可选分支；公共任务只展示承诺和交付。
- 创建草案默认私有，试跑结果真实；发布前展示将共享的内容与范围，停用有明确状态。
- 验收页面的反馈共享默认不选，用户可以接受交付而不共享方法或反馈。
- 展示授权结论与来源、修订和适用范围；私人运行出错时，共同视图只显示影响和下一步。

**交付与验收**：G4-F，A13–A14；两账号交叉查看及直接访问 URL 都遵守边界，创建 / 样例 / 发布 / 停用状态与服务一致。

## 每阶段结束

运行仓库要求的检查和该阶段浏览器验证，确认新增前端被检查覆盖。前端应记录实际浏览器、视口、操作和截图；没有浏览器验证时明确未通过对应项。F0 重点目视与交互验证，F1 起自动化关键协作流程，不写只镜像实现的低价值测试。

按[报告模板](acceptance.md#阶段报告模板)交付小 PR，列出演示模式和真实模式分别通过的内容。不自行部署、合并或继续下一阶段。
