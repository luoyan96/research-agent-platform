# G5a：让小组能开始试用

日期：2026-09-30。**R1—R5 已共同通过。** 证据见 [G5a 报告](reports/G5a-overall-2026-09-30.md)。以下保留实施规格；实际启动见[下一步](../pilot-launch.md)。本批是 B5a/F5a 试用准备；G5b 才是实际小组使用与 P1 判断。不要再以增加能力数量替代开始使用。

## 这次要交付什么

让一位未参与开发的成员，拿到自己的账号和简短说明，就能进入同一平台，接任务、交付、找回工作。维护者能够启动、停止、更新和恢复服务；机器或进程出问题时，知道数据在哪里以及哪些运行需要人工处理。

现有生产模式禁止测试 seed 和 A/B/C 凭据工具；本批正式账号开通与恢复操作流程已验收。SQLite、附件目录、API、worker 和网页都已有基础，本批补最少的运行支持，不换执行底座，不重建后台管理站。

| 工作 | 本批要求 | 停止边界 |
| --- | --- | --- |
| 正式身份 | 通过受控维护命令准备实验室及独立账号、重置凭据和停用账号；有版本/审计与会话撤销规则；不靠直接手改数据库 | 无公开注册、学校 SSO、邮件邀请或共享测试密码 |
| 可重复运行 | 写清构建/迁移/API/worker/网页启动停止、必要变量、健康检查与进程恢复；给出一种可运行的本机或容器验证方式 | 在独立合成目录验证；不自行租云、开公网、装系统级常驻服务或迁移真实数据 |
| 备份恢复 | 数据库和私有附件形成同一恢复点，记录配置版本与所需密钥的独立保管方式；在新路径真实恢复并核对任务、交付、附件与权限 | 可采用明确停写/停 worker 的小组方案；不能运行中仅复制 SQLite 主文件而忽略 WAL/附件 |
| 日常使用 | 一页指引：提出需求、核对分工/日期、成员接受、执行、交付验收、找回请求、保留或撤回授权；按需提示 | 沿用一个入口、总览和任务详情；不加常驻侧栏、入门问卷或新流程中心 |
| 故障处理 | 服务/AI 未配置、登录失效、运行中断、输入不支持时，说明可以采取的动作；保留原输入与原请求 | 不编造运行进度、状态或成本；维护技术细节留在维护说明 |

正式账号停用必须定义对已有任务承诺、会话、排队/运行任务和晚到写回的影响，不能悄悄转交或抹除历史。维护命令应限定实验室、拒绝重复覆盖，并避免在命令参数、日志或公开报告暴露密码。重置后旧会话不能继续操作。用合成姓名和凭据验证这些行为，不创建实际成员账号。

先核对现有生产配置、Cookie/Origin、代理和静态资源访问方式，再写部署说明。目标系统尚未指定，可选一条已验证的通用参考路径并写明环境；将主机、域名、访问范围、维护人和材料范围保留为上线配置项。缺主机不阻止完成工具、恢复演练和本地交付。凭据仍在服务端，前端不包含 DeepSeek 密钥。

## 分工与顺序

后端先核查并交付最小账号/运行/备份恢复接口和命令语义；确实需要 API 变化时才升级共享契约。前端先写短使用指引、梳理现有入口的阻碍，在确切后端 SHA 上验证正式模式的登录与完整交付；不另外设计业务状态。双方从同一 G4a 完整交接提交开始。

部署方案和运行说明先做到可复现，再由用户确定实际主机、参与者与数据范围并执行上线。当前指令不包含正式部署、发送成员通知或开始替用户承诺任务。

## G5a 验收（已通过，保留标准）

| 编号 | 必须提供的证据 |
| --- | --- |
| R1 独立账号 | 不用测试 seed，在干净合成环境建立实验室及至少两名独立成员；成员隔离、重置、停用与旧会话拒绝；密码不进 Git/前端/日志 |
| R2 运行与恢复 | 从文档启动 API/worker/生产网页，关闭浏览器后后台状态持久；服务/worker 重启后已确认事实一致，未知调用不盲目重放 |
| R3 真正恢复备份 | 在另一路径恢复，核对任务/承诺/交付/附件字节与授权、撤权状态；迁移重复执行安全；原环境未被覆盖；说明恢复期间的停写与会话策略 |
| R4 成员可操作 | 新账号按简短指引完成一个合成的安排→承接→交付→验收，找回请求及本人授权；桌面/实际 390×844，正常控制台、生产断服务无演示回退 |
| R5 回归与交接 | 根 CI、受影响服务与浏览器回归；报告确切 SHA/契约、启动停止/故障处理步骤和限制。新增或改变模型路径才需相应真实专项；不重复付费仅证明文案修改 |

R4 的开发者验证只是准备证据，不能算非开发成员独立真实试用。通过 G5a 只说明可以安排试点，不关闭 G5/P1。若出现妨碍基本使用的问题，修复后验收，不靠扩大范围拖延试点。

## 随后的 G5b

用户确定真实参与者、主机与材料访问范围后，按[试点计划](../validation-plan.md)观察至少两项真实交付、至少一名非开发成员独立承接、一次被采用的真实公共 AI 产物，以及下一次自然需求的获准结论复用。实际截止日期重新核对，不沿用历史日期。

记录原来与现在的整理、催问、操作、检查、返工、交接及维护投入，也记录放弃、失败和开发者代操作。未发生自然复用时标为待观察；不安排重复演示来制造留存。小组有用不等于全国市场或付费成立。G4b 私人智能体托管继续后续安排。
