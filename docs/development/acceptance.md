## 怎么判断通过

- 每条记录为“通过 / 失败 / 未验证”，附环境、代码提交、契约版本、操作、预期、实际结果及证据。阻塞属于未验证，写清原因。
- 前端预览、服务联调、真实模型与 Harness 执行分别记录；不能用一个截图或根 CI 通过替代其他证据。
- 同一阶段的前端、后端和联调项均通过才能宣布该关通过。部分可独立工作的内容可继续准备，但不能把未通过的关口改成完成。
- 所有自动验证用合成 A（发起 / 验收）、B（承接）、C（无关或竞争认领）的账号与资料。不同情形用不同任务，明确各自权限。浏览器使用独立登录会话。
- 先核对接口和数据库，再核对界面；验收者可以复现。证据中的令牌、凭据和真实研究内容不得提交 Git。
- 完成代码检查后不无理由重复全量测试；新代码、失败或新风险需要对应验证。每阶段最终报告说明新增应用是否纳入根检查。
