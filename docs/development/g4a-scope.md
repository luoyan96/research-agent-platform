# G4a：把确认的结论用于下一项任务

日期：2026-09-30。**已完成最小范围并通过共同验收。** 证据见 [G4a 报告](reports/G4a-overall-2026-09-30.md)，契约 0.6.2，含普通成员授权找回与撤回修复。以下保留 B4a/F4a 的实施与 A14 验收规格；不等于完整能力平台、G4b/A13 或 P1 完成。

## 用户得到什么

用户完成一次指标核对，可以明确保留“哪个指标已有证据、依据哪版材料、还缺什么”，下次写汇报时选择复用。平台告诉他这条结论来自哪里、是否仍有权使用、是否过时；不会因为验收交付就默认把方法或资料贡献给全组。

入口同时能找回本人发起的生成请求，包括仍在生成和失败的请求，用户不用记住 URL。保留现有简洁入口、协作单、任务详情和公共文本能力，不增加大型知识门户或多套流程。

## 本批最小范围

| 内容 | 必须做到 | 暂不扩展 |
| --- | --- | --- |
| 留存结论 | 用户显式确认内容，绑定来源任务、交付/材料版本、确认人、适用说明、范围和修订记录 | 自动总结后直接设为事实、自动全组共享 |
| 复用结论 | 在新草案或任务中主动选择；展示来源与状态；授权内容实际进入一次真实规划或公共能力调用 | 无边界的全库检索、向量库先行、跨学校知识搜索 |
| 公共能力人工维护 | 维护现有一种公共文本能力的方法版本、获准样例、验证与启用/停用记录 | 通用智能体市场、任意工具/代码安装、私人能力托管 |
| 请求找回 | 本人分页请求列表；新会话可找回排队/运行/失败/取消/完成请求 | 团队成员互看原始对话与私有运行日志 |

结论留存不替代原交付与验收。未分享反馈仍可以验收通过；未选择复用时，不把旧任务内容自动塞进新模型上下文。

## 权限与版本

- 结论来源、内容、适用范围与使用授权分开记录。可读任务不自动意味着可以扩大共享；有能力维护权限不自动获得任务原文或成员方法。
- 复用时同时验证来源访问、目标任务权限和目标读者范围。首版优先拒绝会扩大披露范围的复用；跨范围分享留待明确授权流程，不用复制纯文本绕过来源权限。
- 来源撤权后，列表/计数/详情/旧成功响应/模型派发/写回均重新判断；复用记录保留可审计身份，但不得继续暴露受限内容。派生模型产物及缓存必须记录来源依赖并按规则限制访问，不能只封原链接。已下载内容无法远程追回，应如实说明。
- 来源更新、交付退回或结论修订时标记过时/需复核，保留历史版本；不静默把旧结论换成新结论。重新确认与重新复用是显式动作。
- 公共能力的**方法版本**与启用配置的**代次**分开；运行绑定不可变的方法版本、输入和授权。升级、停用及排队中的旧运行按契约定义处理，不静默换到新方法。现有 B3 的配置 version 不能未经迁移就当作方法发布历史。
- 只收集主动获准的反馈/样例，默认不共享。维护者检查内容与范围，验证候选版本后明确启用。样例应可撤回；撤回阻止后续读取、试跑和新调用，若已进入方法内容须停用或修订受影响版本，不能承诺从模型中“遗忘”从未实施的训练。

方法维护只允许当前内置文本能力的受控配置，不引入动态代码执行。版本试跑仍经真实 Harness、预算、任务/样例授权和运行记录；不以样例通过保证科学正确。样例和真实任务记录不提交公开 Git。

## 页面和分工

前端在验收后的任务上下文提供“保留结论”，展示要留存的文字、来源和范围，由用户确认。新任务的材料选择中可展开“复用已有结论”；未授权、已撤回、过时、无结果有明确反馈。公共能力维护按需展开，仅向有权限者开放；技术 ID/哈希和 provider 详情放在可展开的核对信息中，主要文字说明用户该做什么。

后端先提交版本化 Schema、样例、迁移和具体权限矩阵，再交服务。前端取得确切契约/服务 SHA 后联调。保留 G1—G3 的事务、原 key 重试、会话恢复、冲突比较、快照/轮询、撤权和不伪造成功的规则。
