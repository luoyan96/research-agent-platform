# 组内试点验证计划

对应[产品规划 v0.3](product-plan.md)及[任务分配规则](task-allocation.md)。这是待执行的验证方法，没有已完成的访谈、实验或市场数据。本公开仓库只保留空白模板、可公开样例和汇总决定；实际科研内容与个人使用记录保存在受控空间。

## 1. 首先验证什么

围绕近期真实工作观察三件事：发起人能否从不完整需求得到有用的协作方案；成员能否在不公开私人方法的情况下承接并交付；系统能否减少后续催问、重复解释与任务遗漏。

公共智能体复用、个人能力进化和对外平台供给继续验证，但不能把“每个人贡献自己的方法”作为成功前提。平台先证明能帮助这些人共同完成事情。

## 2. 试点卡

请参与者带一项近期要做或刚做过的工作，说明原来怎么安排、在哪里卡住，而不是只回答是否喜欢一个任务平台。下面内容待团队填写，允许未知项；无需提供私有提示词、源码或私人执行记录。

```text
目标与真实交付物：
任务发起人 / 拟参与成员 / 验收人：
参与者是否开发过本平台：
原有安排方式与主要困难：
发生频率与下一次预计机会：
已有输入、可分享范围与不能分享的内容：
硬性截止及其依据（可以没有）：
本人需要作出的判断与愿意委托的部分：
可用的公共能力及已知限制：
成员愿意公开的专长、可投入时间与承接意愿：
结果采用标准、必要证据及约定的共享交付范围：

```

## 3. 按完整协作观察

**A. 从一句话到方案。** 用户可以带模糊需求开始，观察补问数量与必要性、建议是否可理解、是否误把猜测当约束，以及修改方案需要多少投入。方案可以先人工辅助推演，必须标明模拟与真实执行的区别。

**B. 从建议到承诺。** 让拟参与者决定接受、拒绝、认领或提出条件，观察收到的目标、资料、投入与验收标准是否足够清楚。推荐人选不计为已承接；作者或维护者陪同完成的操作不计为独立使用。

**C. 允许不同执行方式。** 同一协作中可以有本人承担、公共智能体执行、成员使用不公开的方法交付。验收检查约定结果与依据，不要求查看私人实现。平台外完成的工作也允许接续。

**D. 观察变化与交接。** 覆盖一次缺材料、拒绝、转交或范围调整，检查系统是否准确传达影响，是否仍需要重复催问。技术上另行验证并发认领、重复确认、恢复与权限，不能只做顺利演示。

**E. 下一次任务与能力改进。** 等真实需求再次发生，记录是否复用已授权的任务背景或公共能力，以及仍需补充什么。没有下一次机会时标为待观察。个人能力的改进仅由本人自愿报告，不要求交出内部过程作为平台成果。

建议起步包含一位发起人、至少一位未参与开发的承接者，并覆盖共同任务与个人私有范围。用合成的私有能力样例检查隔离，参与者无需为测试公开自己的真实方法。

个人能力的名称、配置、运行日志和私人任务细节不在共同试点记录中。只收集判断产品是否有用所需且参与者同意提供的信息。

## 5. 评价与调整

| 观察结果 | 下一步 |
|---|---|
| 用户容易表达需求，成员能独立承接，成果采用且协调投入下降 | 继续验证下一次使用和更多成员 |
| AI 产生大量任务但组织者仍需逐条整理和催问 | 修正方案粒度、默认行为与反馈方式；不靠增加页面解决 |
| 推荐人选频繁拒绝、投入不真实或时间冲突 | 改进意愿与承诺信息，减少未经验证的推断 |
| 成员因为要披露个人方法而不愿参与 | 修正公开范围和权限，保留只交付结果的参与方式 |
| 公共能力缺口需要某成员来完成 | 按人的承诺安排，不强迫将其方法公开；另行评估是否值得共建公共能力 |
| 能运行但检查返工抵消收益 | 收窄任务边界或改进质量，暂缓扩大能力数量 |
| 任务完成但下一次仍需重复解释 | 检查是否保存了正确且可共享的背景、结论和交接信息 |
| 发生私人内容泄露或越权操作 | 停止受影响的访问或能力，修正并复核后恢复 |
| 跨组使用需要大幅重写规则 | 先识别通用与定制边界，再决定是否扩张 |

统计包含失败、拒绝、放弃和未采用；尚未结束的任务单独列明。没有实际调用的推荐不算成功执行，没有接受的邀请不算完成分配。下一次需求尚未发生时，不推断留存。

比较原有做法时包含协调、准备、检查、返工和维护，不只比较生成速度。同一人重复做同一任务有熟悉效应；回忆估计与实际记录分开，一次性建设投入与每次运行投入分开。小组样本不用于宣称市场规模或统计显著性。

每轮记录支持了哪些假设、哪些仍未成立、继续或停止什么、谁负责修改。跨组付费和外部供给另行验证，不把私人方法的公开数量作为产品指标。
