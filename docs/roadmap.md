# 开发路线图

本文件管理近期顺序。产品目标见[产品规划](product-plan.md)，当前可运行范围见[README](../README.md)。

## 起步：本次迁移

- 独立科研数据核心与十项 Skills 加载包。
- 来源记录、内容检查、构建、类型检查、基础测试与演示。
- Harness 适配源码单独保留；公开 SDK 依赖问题与实际运行待验证。
- 统一 README、协作方式、任务与 PR 模板。

## M0：证明一条真实任务能贯穿平台

| 工作 | 验收 |
|---|---|
| 首批使用情境 | 选择 2–3 类真实任务，明确输入、结果标准和负责人 |
| Harness 接入 | 固定可安装版本，在真实运行环境验证工具和 Skills，而不仅通过替身测试 |
| 成员与项目授权 | 两个成员、两个项目的页面、接口与工具访问遵守同一授权范围 |
| 任务与执行关联 | 提交、运行、待输入、取消和失败状态可追踪到执行记录 |
| 资料与记忆样例 | 新会话取回授权项目资料，能区分候选判断与确认信息 |
| 离线和重启 | 用户离线仍能触发任务；重启后恢复待执行任务，运行中断可见并可处理 |

在 M0 获得证据前，原型界面只能标明实际状态，不把预留页面当成已实现功能。

## M1：组内平台 v0.1

形成统一网页、项目资料、任务中心、可管理记忆与小型能力库。至少两名成员交叉使用能力，至少一人未参与开发；同一次真实任务完成选择、执行、检查、成果留存和下一次复用。

## M2 / M3：独立使用与跨组复用

先观察非开发成员是否能独立完成任务、再次使用及实际净收益，再引入其他课题组和能力作者。公开市场、支付、全校采购和任意第三方代码接入在出现相应证据后规划。

代码检查、科研效果和市场需求分别验证。记录时间与成本时包含人工检查、错误返工和维护投入。
